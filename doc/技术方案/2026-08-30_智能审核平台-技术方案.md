## 1. 目标与范围

### 1.1 要解决的问题

建设可被审批流对接的智能审核引擎：规则专家维护**规则集**与**审核器**；接入方提交多附件内容包，按所选审核器逐条打分，按评估分方式汇总；结果可查询、可改分/标注、可锁定；通过 REST + Webhook 回传。

### 1.2 范围

本期一份方案覆盖 PRD MVP 全部功能：规则集管理、审核器管理、审核任务管理（含引擎）、开放 API、Webhook、管理端查询/配置接口及管理端 Web 部署。

**不包含：** 审批流本身、复核台、自建 Agent 运行时、多租户、脚本规则引擎、按附件拆多套分数。

### 1.3 设计前共识（已确认）

| 项 | 结论 |
|---|---|
| 部署架构 | **重新设计**（新产品，无既有部署可复用） |
| 技术栈 | Java 六层 Maven + 本期设计管理端 Web 接口与部署 |
| 方案切分 | **一份方案覆盖整个 MVP** |
| 包前缀 | `com.audit.platform` |
| 异步打分 | **应用内线程池**，本期不上 MQ 产品 |
| 附件存储 | **对象存储 TOS**（S3 兼容），库中只存对象键与元数据 |
| 鉴权 | 开放 API：**API Key**；管理端：**SSO**（方案留对接点） |
| 租户 | **单租户**，表不带 `tenant_id` |
| Agent | 领域网关 + **Mock 适配器**可跑通，真实平台可替换 |
| 写接口 | 对外也统一 **POST 命令**（不用 PUT/PATCH/DELETE） |
| Webhook | **独立投递队列** + 指数退避 + 失败可查/死信（用 Redis 延迟队列实现，不引入 MQ） |
| 性能 | 按生产设计；具体数字采用下文「生产基线假设」，上线前按压测可调 |

## 2. 架构设计

### 2.1 应用架构

新品，仓库内无 Java 业务代码。后端按六层新建；管理端为独立 SPA，只调 HTTP。

#### 2.1.1 分层依赖

```text
adapter → application → client
application → domain
application → infra（仅 QueryService 注入 Mapper；禁止注入 Repository/Gateway）
infra → domain
domain → facade
adapter → client
```

Spring Bean 一律 `@Resource` 字段注入。

#### 2.1.3 模块调用关系

**命令类（HTTP 管理端 / 开放 API）：**

```text
CommandController → CommandService
  →（校验）QueryService
  → Factory.create / createByNum
  → 领域动作（内部 Repository.save / Gateway / DomainEventPublisher）
  → 返回 num 或 DTO 标识
```

**命令类（异步打分）：**

```text
EvaluationCreated 事件监听器 → EvaluationCommandService.runPipeline(num)
  → Factory.createByNum → parse / classify / score 领域动作
```

**命令类（Webhook）：**

```text
领域事件监听器 → AccessCommandService.enqueueWebhook
定时任务 WebhookDispatchJob → AccessCommandService.dispatchDue
```

**查询类：**

```text
QueryController → QueryService → Mapper（LambdaQueryWrapper）→ DTO
```

#### 2.1.4 同步 / 异步边界

| 场景 | 同步/异步 | 触发 | 消费 | 说明 |
|---|---|---|---|---|
| 创建规则集/审核器/凭证 | 同步 | CommandController | CommandService | 立即返回编号 |
| 创建审核任务 | 同步落库 + 异步打分 | Open/Admin Command | Listener + 线程池 | 创建接口不跑机评 |
| 逐条打分 | 异步 | `EvaluationReceivedEvent` | `EvaluationPipelineListener` | `@Async` 线程池 |
| 改分/标注/锁定 | 同步 | CommandController | CommandService | 即时重算；再发 updated/finalized |
| Webhook HTTP | 异步 | 领域事件 | Redis 延迟队列 + 定时扫描 | 与打分线程池隔离 |
| 管理端/开放查询 | 同步 | QueryController | QueryService | 只读 |

创建任务后**不得**在 HTTP 线程内调用 Agent。流水线失败写 `failed`，不抛给调用方堆栈。

#### 2.1.5 与现有代码关系

无既有 Java 模块。`doc/ui/2026-08-30_智能审核平台/web` 仅作交互对照，**不作为后端实现**。管理端可按同一信息架构重接真实 API。

### 2.2 部署架构

新产品，重新设计应用/前端运行拓扑。数据库、Redis、TOS 使用云服务，不设计其底层集群。

#### 2.2.1 运行拓扑

```mermaid
flowchart LR
  Expert[规则专家浏览器] --> CDN[CDN / 静态托管]
  CDN --> AdminWeb[管理端 SPA]
  Integrator[接入方系统] --> GW[API 网关 / Nginx]
  AdminWeb --> GW
  GW --> App1[audit-platform-api 实例1]
  GW --> App2[audit-platform-api 实例2]
  App1 --> MySQL[(云 MySQL)]
  App2 --> MySQL
  App1 --> Redis[(云 Redis)]
  App2 --> Redis
  App1 --> TOS[(云 TOS)]
  App2 --> TOS
  App1 --> SSO[企业 SSO]
  App1 --> Agent[Agent 平台]
  App1 --> CB[接入方回调 URL]
```

prod 两实例；线程池打分与 Webhook 扫描在**每个实例**上运行。任务认领用 Redis 锁（`eval:pipeline:{num}`），避免双实例重复打分。Webhook 投递用 `webhook:dispatch:{num}` 锁。

#### 2.2.2 实例清单

| 应用 | 类型 | 部署方式 | 实例数 | 访问入口 | 是否新增 |
|---|---|---|---|---|---|
| audit-platform-api | 后端 Spring Boot | 容器 / 云主机，前置网关 | prod **2**（可水平扩）；test 1；dev 1 | `/admin/v1/**`、`/open/v1/**` | 是 |
| audit-platform-admin | 管理端 SPA | TOS + CDN | **1** 套静态资源 | `https://audit-admin.{env}.example` | 是 |

无独立 Worker 进程：打分与 Webhook 均在 api 进程内。若后续在途任务超过单进程容量，再拆 Worker，不在本期部署。

#### 2.2.3 环境差异

| 项 | dev | test | prod |
|---|---|---|---|
| api 实例 | 1 | 1 | 2 |
| 域名 | localhost / 内网 | test 网关 | 正式网关 |
| SSO | Mock 头 / 开发回调 | 测试 SSO | 生产 SSO |
| Agent | MockGateway | Mock 或测试 Agent | 可替换真实适配器 |
| TOS bucket | `audit-dev` | `audit-test` | `audit-prod` |
| Webhook 真实外呼 | 默认关，可配白名单 | 开 | 开 |
| 线程池 | 小（core=2） | 中（core=4） | 大（core=8，max=16） |

#### 2.2.4 云服务依赖（只说明连接关系）

| 云服务 | 用途 | 连接方 | 失败策略 |
|---|---|---|---|
| 云 MySQL | 业务表 | api | 连接池；写失败回滚；读失败返回 5xx |
| 云 Redis | 分布式锁、Webhook 延迟队列、幂等 | api | 锁失败快速返回冲突；队列失败记表补偿 |
| 云 TOS | 附件原文 | api | 上传失败任务不可创建；下载/解析失败见领域规则 |
| 企业 SSO | 管理端登录 | 网关 + api 校验 token | token 无效 401 |
| Agent 平台 | Agent 审核器逐条判断 | api GatewayImpl | 单条超时失败；全部失败则任务 failed |
| 接入方 HTTP | Webhook | api | 指数退避；入死信；不影响已算出的分 |

#### 2.2.6 扩缩容与高可用

- api **无状态**，会话不落本地。扩容加实例即可。
- 打分与 Webhook 靠 Redis 锁互斥；实例挂掉后锁过期，其他实例的定时任务/监听可补偿（流水线以任务状态为准，`received/parsing/...` 可恢复）。
- TOS 与 MySQL 由云高可用承担。
- 管理端静态资源 CDN 回源 TOS。

## 4. 领域层设计

### 4.1 业务层级划分

| 层级 | 领域 | 说明 |
|---|---|---|
| 配置 | ruleset | 规则集主档、版本、规则、评估分方式、发布 |
| 配置 | auditor | 审核器；Agent 目录缓存 |
| 执行 | evaluation | 内容包、匹配规则集、打分、改分、标注、锁定 |
| 接入 | access | API 凭证、回调订阅、Webhook 投递单 |

跨聚合只引用 `num`。任务绑定规则集版本时**快照**规则内容，之后改规则不影响旧单。

---

### 4.2 规则集（ruleset）

#### 4.2.1 领域模型

```mermaid

        <<factory>>
        +create(name, description) RuleSet
        +createByNum(num) RuleSet
    }
    class RuleSetGateway {
        <<gateway>>
        +generateNum() String
        +generateVersionNum() String
        +generateRuleNum() String
    }
    class RuleSetRepository {
        <<repository>>
        +save(RuleSet)
        +findByNum(num) RuleSet
        +deleteByNum(num)
    }
    class RuleSet {
        <<aggregate root>>
        +Long id
        +String num
        +String create_no
        +String update_no
        +String name
        +String description
        +Boolean enabled
        +String currentPublishedVersionNum
        +RuleSetRepository repository
        +RuleSetGateway gateway
        +DomainEventPublisher domainEventPublisher
        +save(operatorId)
        +delete(operatorId)
        +updateProfile(name, description, operatorId)

        +moveRule(ruleNum, direction, operatorId)
        +publish(operatorId)
        +disableCurrentPublish(operatorId)
    }
    class RuleSetVersion {
        <<entity>>
        +Long id
        +String num
        +String create_no
        +String update_no
        +Integer versionNo
        +String status
        +Boolean currentFlag
        +String scoreMode
        +BigDecimal overallPassScore

        +delete(operatorId)
    }
    class RuleItem {
        <<entity>>
        +Long id
        +String num
        +String create_no
        +String update_no
        +String name
        +String standard
        +BigDecimal minScore
        +BigDecimal maxScore
        +BigDecimal passScore
        +BigDecimal weight

        +String negativeExample

        +delete(operatorId)

    RuleSetFactory ..> RuleSet
    RuleSet --> RuleSetVersion
    RuleSetVersion --> RuleItem
    RuleSetVersion --> ScoreMode
```

| 对象 | 类型 | 属性要点 | 关系 |
|---|---|---|---|
| RuleSet | 聚合根 | num=`RS-0004` 系统生成；name 用户填；enabled | 1:N Version |
| RuleSetVersion | 实体 | DRAFT 无 versionNo；PUBLISHED 单调版本号；同时最多一个 current 已发布 | 属于 RuleSet |
| RuleItem | 实体 | 分数契约 + 自然语言标准 | 属于 Version |
| ScoreMode | 值对象 | ALL_PASS / WEIGHTED_SUM / VETO_WEIGHTED | 挂在 Version |

软删除字段不进入领域模型。

#### 4.2.2 领域动作

| 聚合/实体 | 领域动作 | 职责 | 前置条件 | 后置条件/规则 | 领域事件 |
|---|---|---|---|---|---|
| RuleSet | save(operatorId) | 持久化聚合 | 通过 domainValidate | 写库 | RULE_SET_SAVED |
| RuleSet | delete(operatorId) | 删除主档 | 无进行中任务依赖（由应用层 Query 预检） | 仓储删除 | RULE_SET_DELETED |
| RuleSet | updateProfile(name, description, operatorId) | 改名称说明 | 已启用或停用皆可 | 编号不变 | RULE_SET_SAVED |
| RuleSet | setEnabled(enabled, operatorId) | 启停 | 停用后新任务不可指定 | current 发布仍保留供历史任务 | RULE_SET_ENABLED_CHANGED |
| RuleSet | createDraft(basedOnVersionNum, operatorId) | 新建草稿或从某版本复制 | 同时仅允许一个 DRAFT | 复制规则与评估分方式 | RULE_SET_DRAFT_CREATED |
| RuleSet | changeScoreMode(scoreMode, overallPassScore, operatorId) | 改评估分方式 | 目标版本必须是 DRAFT | 加权类 overallPassScore&gt;0 | RULE_SET_SAVED |
| RuleSet | upsertRule(..., operatorId) | 增改规则 | DRAFT | min&lt;max，通过分在区间内；加权权重&gt;0 | RULE_SET_SAVED |
| RuleSet | removeRule(ruleNum, operatorId) | 删规则 | DRAFT | — | RULE_SET_SAVED |
| RuleSet | moveRule(ruleNum, direction, operatorId) | 调序 | DRAFT | 只影响展示序 | RULE_SET_SAVED |
| RuleSet | publish(operatorId) | 发布草稿 | 校验完整；至少 1 条规则；红线+加权至少 1 条红线 | 草稿变 PUBLISHED 并 current；旧 current 变 ARCHIVED | RULE_SET_PUBLISHED |

#### 4.4.2 领域动作

| 动作 | 职责 | 前置 | 后置 | 事件 |
|---|---|---|---|---|
| save / delete | 持久化/删除试评或误单 | delete 仅 trial 或管理员策略 | — | EVALUATION_SAVED / DELETED |

| assignRuleSet | 指定/重评规则集 | TYPE_PENDING 或 SCORED 未锁定 | 清人工分，重新 startScore | EVALUATION_RECLASSIFIED |
| startScore | 加载规则快照并逐条打分 | 已绑定可用发布或试评草稿 | 调 Gateway.score | — |
| applyMachineScores | 写入逐条结果并汇总 | SCORING | SCORED；按评估分方式算 passed | EVALUATION_SCORED |

| patchScore | 人工改分即时重算 | SCORED | 展示分用人分 | EVALUATION_UPDATED |
| addAnnotation | 标注不改分 | SCORED | — | EVALUATION_UPDATED |
| finalize | 锁定 | SCORED | FINALIZED 只读 | EVALUATION_FINALIZED |

```mermaid
  I->>GW: httpPost(callbackUrl, payload)
  alt 2xx
    I->>I: SUCCESS
  else 未超 max-retry
    I->>GW: enqueueDelayed(backoff)
    I->>I: RETRY
  else
    I->>I: DEAD
  end
  I->>Repo: save
```

其余动作：校验 → save → 事件。

#### 4.5.3 领域规则

| 对象 | 规则 | 违反 |
|---|---|---|
| Credential | 明文密钥只在创建响应出现一次 | 不落库 |

| IntegrationSetting | 未订阅事件不投递 | 跳过 |
| WebhookDelivery | trial 任务不入队 | 跳过 |

### 7.6 定时任务

| 任务 | cron | 调用 | 幂等 | 并发 | 失败 |
|---|---|---|---|---|---|
| WebhookDispatchJob | `*/5 * * * * ?` | AccessCommandService.dispatchDue | deliveryNum 状态机 + Redis 锁 | 单实例锁 `lock:job:webhook-dispatch` 也可多实例抢锁逐条 | 告警 DEAD 增量 |
| AgentCatalogJob | `0 0 * * * ?` | AuditorCommandService.syncAgentCatalog | 整表覆盖目录 | `lock:job:agent-catalog` | 保留旧目录，日志告警 |
| PipelineRecoverJob | `0 */2 * * * ?` | 查询卡住的 RECEIVED/PARSING/SCORING 超时单并 runPipeline | 状态+锁 | `lock:job:pipeline-recover` | 超次数 fail |

```mermaid
sequenceDiagram
  participant J as WebhookDispatchJob
  participant S as AccessCommandService
  J->>J: tryLock lock:job:webhook-dispatch
  J->>S: dispatchDue()
  J->>J: unlock
```

PipelineRecoverJob / AgentCatalogJob 时序相同：抢锁 → CommandService → 解锁。

### 7.7 事件监听

| 监听器 | 来源 | 事件 | 调用 | 幂等 | 重试/DLQ | 告警 |
|---|---|---|---|---|---|---|
| EvaluationPipelineListener | Spring DomainEvent | EVALUATION_SAVED / RECLASSIFIED / PARSED / CLASSIFIED | runPipeline 步进 | eval 状态机 + pipeline 锁 | 捕获异常写 fail；不自动无限重试 | 是 |
| WebhookEnqueueListener | Spring DomainEvent | CLASSIFIED/SCORED/UPDATED/FINALIZED/FAILED | enqueueWebhook | eventId 唯一索引 | 入队失败写表 PENDING 由 Job 补 | 是 |

## 12. 接口与数据契约（摘要）

统一响应：

```json
{"code":0,"message":"ok","data":{}}
```

业务错误：`code!=0`，如 `RULE_SET_NOT_FOUND`、`EVALUATION_LOCKED`、`AUDITOR_DISABLED`。

任务详情 `data` 至少包含：status、ruleSetNum/versionNo/source、auditorNum/kind、attachments、results（机评/人评/展示分/证据）、summary（scoreMode、totalScore、passed、complete）、timeline（可由日志表后补，本期用领域事件表或任务内 JSON 列可选；**本期 timeline 由 evaluation 操作写 `evaluation_timeline` 可在实现时按同规范加表**。为实现闭环，查询 DTO 的 timeline 可先由 webhook + 结果变更时间拼装；完整时间线建议实现阶段增表 `evaluation_timeline`（字段同审计约定）。）

### 14.1 PRD 覆盖缺口

### 14.2 规约对齐（与 impl-*-module 一致）

| 项 | v1.0 写法 | 实现写法 |
|---|---|---|
| 统一返回 | `code/message`，成功 0 | facade `Result`：`code/msg/data/rows`，成功 **200** |
| 业务异常 | BizException | `BusinessException` |
| 事件发布 | `publish` | `DomainEventPublisher.send(DomainEventDTO)` |
| 审计 Java 字段 | create_no | DomainEntity：`createId`/`updateId`；表列仍为 `create_no`/`update_no`，infra 映射 |
| 通用请求 | OperatorContext | 另保留 `CommonRequest.operatorId`；Filter 写入后 Controller 填入 Param |
| 分页 | PageResult | `Result.ok(rows)` + 可另增 client `PageDTO{total,pageNo,pageSize,list}` |
